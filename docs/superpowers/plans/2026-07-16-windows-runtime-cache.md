# Protected Windows Runtime Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace per-launch Windows runtime snapshot copies with a validated, immutable, content-addressed per-user cache and generate a protected `qt.conf` beside every staged executable.

**Architecture:** A new `tools/windows_runtime_cache.py` module owns cache keys, manifests, publication, validation, repair, leases, and bounded cleanup. `RuntimeAuditLease` remains the launcher-facing owner of held source and cache-object handles; the app and CTest launchers keep their existing closure boundaries while declaring dependency keys, generator inputs, and protected Qt paths to the cache.

**Tech Stack:** Python 3 standard library, `ctypes` Win32 known-folder/filesystem/ACL APIs, `unittest`, existing Windows launcher tests.

## Global Constraints

- This is runtime isolation and reproducibility work, not cybersecurity work.
- The production cache root is `<FOLDERID_LocalAppData>/OpenLiveReplay/launch-cache/v2`; inherited environment variables cannot select it.
- The lexical root and every created parent must match their handle-final paths and contain no reparse point.
- Held source descriptors bind handle-final path, filesystem device/inode identity, byte size, and SHA-256, and publication copies from those held streams.
- Layout names and destination components pass strict Win32 validation; destination collision normalization and layout identity use Windows-local `ntpath.normcase()`, never Unicode `casefold()`.
- Launcher context and generated-entry inputs are recursively validated and detached into plain JSON trees before keying; non-string keys, unsupported values, cycles, NaN, and infinities are rejected.
- JSON strings and mapping keys containing any Unicode surrogate code point are rejected before UTF-8 encoding.
- Held descriptors require a canonical strict-component drive-rooted/UNC final path with no extended/device namespace prefix, exact nonnegative integer device/inode/size fields, and lowercase 64-hex SHA-256; dependency keys use the same digest format and must be unique.
- Published objects are immutable read/execute trees; `manifest.json` is written last before ACL conversion and atomic no-replace publication.
- Cache hits revalidate key, context, exact file set, file hashes, generated bytes, final paths, absence of reparses, and denied mutation access before launch.
- Active objects stay held until `RuntimeAuditLease.close()` and cleanup must skip them.
- Every staged `.exe`, including CTest, build tests, runtime tools, external tools, Qt tools, and the app, receives a launcher-owned `qt.conf`; source `qt.conf` files are replaced, not copied.
- Maximum published size is 8 GiB, maximum object count is 256, maximum unused age is 14 days, staging retention is one hour, access-stamp writes are throttled to one hour, and cleanup is throttled to one day.
- App cold preparation is at most 30 seconds, 256 MiB, and 2,048 logical files; focused CTest cold preparation is at most 30 seconds, 256 MiB, and 4,096 logical files; full CTest cold preparation is at most 120 seconds, 2 GiB, and 16,384 logical files.
- App and focused CTest warm preparation are at most 5 seconds; full CTest warm preparation is at most 8 seconds; every warm preparation has zero misses and zero payload-written files or bytes.
- Invalid, partial, corrupt, aliased, writable, contended, or over-capacity cache state fails before child-process creation and never falls back to mutable source trees.
- Do not start CTest or an app until Tasks 1–7 pass; Task 8 is the exclusive runtime-evidence lane.
- Stage only paths named by each task. Never use `git add -A`, never bypass hooks, and include `Co-Authored-By: Claude <noreply@anthropic.com>` in every commit.

evaluate successfully on Python 3.8+, unlike PEP 604 expressions evaluated in
an assignment.

`canonical_json()` must recursively normalize a JSON value and then use `json.dumps(value, sort_keys=True, separators=(",", ":"), ensure_ascii=False, allow_nan=False).encode("utf-8")`. The recursive normalizer accepts `Mapping`, tuple, list, string, finite float, integer, Boolean, and `None`; it produces only detached plain dictionaries/lists/scalars, converts tuples to lists, requires string mapping keys, detects cycles, and raises `RuntimeError` containing `invalid JSON value` for unsupported or non-finite values. Scan every string value and mapping key for code points U+D800–U+DFFF and raise the same located `RuntimeError` before UTF-8 encoding. Normalize `context` and every `GeneratedLayoutEntry.inputs` before placing them in the returned key input, including `MappingProxyType` implementations.

`layout_key()` must first validate `name` as exactly one strict safe Win32
component. It must consume the ordered entry-pair sequence directly and
validate every destination component before constructing any destination
dictionary. Reject absolute, anchored, empty, and parent paths; trailing dot
or space; `:`, `<>:"/\\|?*`; ASCII controls 0–31; and DOS basenames `CON`,
`PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, `CONIN$`, `CONOUT$`,
`CLOCK$`, `COM¹`–`COM³`, and `LPT¹`–`LPT³` even with extensions.
Normalize components with `ntpath.normcase()` because this is a Windows-local
cache; this provides stable ASCII behavior in platform-neutral tests without
Unicode `casefold()` conflation. Store the normalized layout name in the key
input so case-only spellings share one identity; Task 3 retains requested
spelling as separate manifest metadata. Require every dependency key to be
exactly 64 lowercase hexadecimal characters, reject duplicates, copy and sort
the sequence, and require every generated policy to be a nonempty string. A
held descriptor's final path must be drive-rooted or UNC; its device, inode,
and size must each have exact type `int` (not `bool`) and be nonnegative; its
SHA-256 must be exactly 64 lowercase hexadecimal characters. Independently
encode the normalized layout name and
destination, held final path/device/inode/size/
digest, literal size/digest, and generated policy/normalized inputs, and return
`sha256(canonical_json(key_input)).hexdigest()` plus that detached key input.
Requested destination spelling must not appear anywhere in `key_input`.
Never construct a `Path`-keyed entry dictionary: Windows `Path` hashing can
erase an ASCII case collision before validation.

Held final paths additionally reject extended/device/NT namespace prefixes
(`\\?\`, `\\.\`, `\??\`, and variants). Parse only ordinary letter-drive and
UNC anchors; validate every remaining component plus UNC server/share with the
strict Win32 component validator; and store a slash-stable
`ntpath.normcase()` identity in `key_input`. Actual path spelling is excluded
from the key and may be retained only as Task 3 manifest source metadata.
